# Cablester 开发规划

## 目标

Cablester 的核心不是一次性通过关卡，而是让玩家把固定的大地图逐步练成一条高速移动路线。浏览器原型只负责尽快验证 3C、资源循环和旋转空间；Godot 阶段负责正式的内容生产、工具链和表现。

## 已确认的设计支柱

1. 软绳是高频移动能力：玩家通过挂点、物理摆荡、加速收绳和松绳时机控制速度曲线；绳索只能主动缩短，不能主动放长。
2. 硬杆是撑杆跳能力：消耗更多能量，将角色以固定杆长连接到普通表面或伤害区域的底部碰撞面，主动释放时保留切向速度。
3. 固定地图强调可学习性：第一次允许观察与失败，熟练后可以高速连续穿越。
4. 旋转同时承担表演和挑战：可以短暂打乱方向，但不能让规则和失败原因变得含糊。
5. 血量提供受伤容错；蓝量是路线预算。所有依赖资源的主线路径都必须具备防软锁措施。
6. 能力授予与来源解耦：剧情、物品、技能点和调试入口最终都只授予同一个能力 ID。
7. 冲刺提供一次可控的空中改线：默认朝面向方向，组合方向键时支持八方向，并能把高速动量传递给随后连接的绳索或硬杆。

## 阶段一：浏览器 3C 原型

### 里程碑 A：可运行骨架

- 无外部运行时依赖的 Canvas 工程。
- 固定时间步物理、键鼠输入、相机和调试信息。
- 所有手感参数集中配置，便于快速调整。

### 里程碑 B：核心移动

- 跑动、跳跃、土狼时间、跳跃预输入。
- 墙抓和墙跳。
- 方向式软绳瞄准，支持锚点、墙壁、天花板和斜面；包含可见的发射/回收过程、物理摆荡、`W` / 上方向键快速加速收绳、最短长度完成加速、松绳保留动量和张力驱动的软绳曲线。
- 摆荡方向输入采用起步脉冲和基于已有角速度的泵速/制动，不允许持续输入形成抵消重力的静态平衡。
- 绳索与硬杆连接期间，`A/D` 转化为平滑切向力；同角速度方向加速，反方向优先制动。
- 硬杆连接角色与普通表面或伤害区域的底部碰撞面，生成后锁定长度，只允许绕命中端旋转，直到玩家再次按 `F` 释放。
- 二段跳通过统一能力授予接口解锁。
- 八方向冲刺通过统一能力授予接口解锁；空中一次、落地恢复，世界旋转后仍按屏幕方向解释输入。
- 移动或冲刺途中连接绳索/硬杆时保留切向惯性，约束运动通过独立阻尼逐渐减速，主动释放继续保留当前速度。

### 里程碑 C：关卡与资源

- 血量、蓝量、每秒伤害、伤害区单向底座、无敌帧和安全点复活。
- 蓝量拾取物、检查点恢复和保底回蓝。
- 固定测试关卡，包含安全路线、连续荡绳路线和一个旋转房间。
- 世界旋转、屏幕方向输入和重力同步变化。

### 浏览器原型的技术验收

- 本地启动不依赖打包器或第三方库。
- 固定时间步下，30/60/120Hz 显示刷新不会明显改变移动结果。
- 蓝量耗尽时不存在必须退出游戏才能解除的卡死。
- 高速状态下会预览当前绳索目标，并且不会自动锁定超出范围的锚点。
- 同一个伤害区域不会在无敌帧内连续扣血。
- 角色进入伤害坑后不会穿过底部；未及时离开时每秒扣 1 血。
- 旋转后左右输入仍对应屏幕左右，重力始终表现为屏幕向下。
- 死亡、坠落和手动重置都回到最近检查点。

### 体验验收门槛

这一部分必须由实际试玩确认，自动测试不能代替：

- 连续荡绳是否形成不同于普通钩爪的节奏。
- 从第一次试错到熟练通过，效率是否有明显提升。
- 软绳耗蓝是否促进路线规划，而不是压制核心玩法。
- 旋转的混乱是否可学习、失败原因是否清楚。
- 高速路线是否有足够的提前观察和记忆空间。

只有这些问题得到肯定或完成相应调整后，才进入 Godot 迁移。

单项能力使用 `L0–L4` 验收等级。只有达到 `L1` 及以上的能力可以进入 Godot 同步实现；`L0` 继续留在 Web 原型中迭代。等级定义和当前状态见 [`ACCEPTANCE_LEVELS.md`](ACCEPTANCE_LEVELS.md)。

## 阶段二：Godot 迁移

目标版本暂定 Godot 4.x。开始迁移时先确认具体小版本，不在浏览器原型阶段提前依赖某个 Godot API。

### 迁移原则

- 迁移行为规则和参数，不逐行翻译浏览器代码。
- `CharacterBody2D` 承担角色运动；能力使用独立组件或资源配置。
- `AbilityDefinition`、`AbilityGrant`、`ResourcePool` 与关卡来源解耦。
- 绳索生命周期、绳索约束、张力绳形、切向摆荡输入、约束阻尼、八方向冲刺、目标可见性、硬杆结构、伤害区底座、猛击时停和旋转重力分别作为独立系统。
- 测试关卡保持锚点位置、资源预算和挑战顺序一致，用于对比两端手感。

### Godot 里程碑

1. 复现浏览器版基础跑跳和相机。
2. 复现软绳发射回收、约束和绳形，完成同路线时间和出绳结果对比。
3. 复现冲刺、硬杆、惯性传递、血蓝、伤害与检查点。
4. 复现旋转房间和屏幕方向输入。
5. 建立关卡数据、能力资源和调试面板。
6. 浏览器原型冻结为手感参考，正式内容转入 Godot。

## 已识别风险与约束

| 风险 | 首版约束 |
|---|---|
| 核心移动耗蓝导致玩家不愿荡绳 | 软绳低消耗；连续路线放置能量；安全地面提供保底恢复 |
| 蓝量耗尽造成软锁 | 主线路径进行资源预算；检查点恢复；提供手动回到安全点 |
| 高速锁错锚点或表面 | 方向射线、第一层可见性拦截、目标表面高亮、宽容差吸附、范围限制和确定性排序 |
| 硬杆产生不可控组合 | 首版一次只允许一根，连接新杆前必须主动释放旧杆 |
| 旋转造成输入反向 | 输入保持屏幕空间，转换到当前世界方向 |
| 旋转导致眩晕 | 表演与挑战使用不同速度，并预留降低动态效果选项 |
| 受伤后被机关连续击杀 | 单向坑底、每秒一次伤害、击退、脱离跳和安全点复活 |
| 获得能力后破坏关卡顺序 | 能力门使用标签查询；维护区域依赖图和后备出口 |
