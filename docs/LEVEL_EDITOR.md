# 关卡工坊与物件数据

浏览器原型内置“关卡工坊”，从开始菜单即可进入。它同时承担手工关卡编辑器和确定性关卡生成器两种职责。

## 基本工作流

1. 从左侧物件库选择一种物件，在画布中点击放置；
2. 选中物件后拖动位置，或在右侧属性栏精确输入坐标和参数；
3. 使用种子、路线长度与难度生成基础路线，再手工调整；
4. 试玩当前草稿，确认后保存到当前设备；
5. 使用 JSON 导入/导出跨设备传递关卡。

编辑器支持网格吸附、画布平移/缩放、复制、删除、撤销和重做。内置关卡会以副本形式打开，不会覆盖源码中的关卡定义。

## 统一物件格式

工坊使用版本化的关卡文档。未来关卡逻辑只需描述“什么位置有哪一种物件”：

```json
{
  "schemaVersion": 1,
  "metadata": {
    "id": "custom-demo",
    "name": "演示关卡",
    "category": "自定义关卡",
    "summary": "物件格式示例"
  },
  "bounds": { "x": -500, "y": -450, "w": 2800, "h": 1700 },
  "startingAbilities": ["rope", "dash", "wallGrab"],
  "objects": [
    {
      "id": "platform-1",
      "type": "platform",
      "position": { "x": 120, "y": 640 },
      "properties": { "w": 360, "h": 120 }
    },
    {
      "id": "anchor-1",
      "type": "anchor",
      "position": { "x": 520, "y": 280 },
      "properties": { "anchorType": "rope" }
    }
  ]
}
```

`type` 对应物件库中的类型，`position` 是所有物件共享的位置，`properties` 只保存该类型需要的参数。游戏开始前，文档会被编译为当前物理与渲染系统使用的 `platforms`、`hazards`、`anchors` 等集合，因此原有关卡运行逻辑无需重写。

## 当前物件库

- 关卡结构：出生点、终点、检查点；
- 地形：平台、斜面；
- 危险与机关：伤害区、风场、旋转触发区；
- 交互物件：绳索锚点、猛击支点、能量球、能力拾取；
- 引导与装饰：提示牌、背景光晕。

物件定义集中在 `src/level-objects.js`。新增类型时，需要在物件库中定义默认属性，并在编译逻辑中指定它对应的运行时集合。

## 本地保存范围

“保存”使用浏览器本地存储，只在当前浏览器和设备中可用。需要进入源码、版本控制或共享给其他人时，应导出 JSON；未来接入服务端后，可以保持同一文档格式，将存储层替换为关卡数据库。
